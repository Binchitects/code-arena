# Measurements for 0.3

Built with `--release` in the build image on the build host (Linux x64, 24 cores); each figure the median of 20 runs
(30 for `version`).

| what | 0.2 | 0.3 | the plan's target |
|---|---|---|---|
| the static Linux binary (x64, musl) | | 11.1 MB | |
| `code-arena version` (settings, the connection and the edition read) | | 1.9 ms | |
| the session store, 10,000 messages: append a message, on disk | 0.35 ms | 0.40 ms | |
| open the store and read the last 30 turns | 1.25 ms | 0.60 ms | ≤ 30 ms |
| read the 30 turns before those | 0.75 ms | 0.33 ms | |
| what the model reads (from the last compaction) | 1.54 ms | 0.71 ms | |
| search the folder's sessions (FTS5) | 7.6 ms | 3.57 ms | |

The store's schema 2 (Arena's ids, the chat's link, the plan) costs nothing measurable; the faster reads are the
host's load on the day, not a change. `cargo run --release -p ca-session --example measure` gives them.

The binary grew with the chat's sync, memory, the plan, checklists, providers (Anthropic's Messages API) and the 35
built-in skills (284 KB of them) built in. Chat sync's own cost is a send per message in the background; the turn
never waits for it.

## On a real Arena (8.0, the build host's own deploy), 2026-11-26

Run by hand and by a driver against the live server, the person's own sign-in:

- `doctor`: every feature 8.0 has is there; `checklists.edit`, `project_work` and `automation.*` are not (as 8.0
  answers).
- A chat's first turn makes its chat and holds it; `/sync` after it: Arena has every message. `/web` lists the
  sessions' chats with their messages; `-p --continue` goes on in the same chat.
- `/memory` lists Arena's memories; `/checklist`, `/projects`, `/assistant` answer from Arena; `/context` counts with
  the model's own tokenizer.
- A message written on the web while the prompt waits comes in with the web's answer (`From the web: …`).
- Not verified by Code Arena's own tests: a message queued on the web during a turn. Arena 8.0 takes into a Code Arena
  turn only queued messages that name no model, and the web chat names one: those wait for the turn's end and the web
  answers them then.
- Each request came 0% cached across runs (66% within one turn): the engine's cache across runs is the 0.4 item
  "llama.cpp's shared cache asked again".
